Automated model for analysis of .IQ and .wav files along with signal parameter extraction

Upload a recording. SanketSetu extracts the signal parameters, identifies the modulation, demodulates it, finds the error-correcting code (convolutional, Reed-Solomon, LDPC) and interleaving, correlates the bit stream to separate header from payload, and recovers the message.

iv.

FEC decoding

Brief: short-constraint convolutional codes with Viterbi, RS block codes, concatenated codes, LDPC

See it: choose the preset LDPC code or Reed-Solomon + LDPC and read the decoding cards.

Open the analyzer
  • Convolutional + ViterbiWorking

    Code polynomials identified blindly, then hard-decision Viterbi decoding.

  • Reed-SolomonWorking

    RS(255,223), RS(204,188) and shortened codes, with corrected and uncorrectable symbols reported.

  • Concatenated codesWorking

    Reed-Solomon outside, convolutional inside, decoded end to end.

  • LDPCPartly

    Min-sum decoder. Built-in codes are recognised and their start found automatically; for any other code (CCSDS, 5G, Wi-Fi) you upload its parity-check matrix.

v.

Bit-stream correlation

Brief: identify header and payload

See it: open De-interleave, FEC and correlation and look at the frame-structure chart.

Open the analyzer
  • Frame lengthWorking

    Found by folding the bit stream at trial lengths and measuring how well the rows line up.

  • Sync wordWorking

    The repeating pattern is located and named when it is standard, for example the CCSDS marker 1ACFFC1D.

  • Header and payloadWorking

    Columns that stay predictable from frame to frame form the header; the rest is payload.

  • ConditionPartly

    Needs a repeating sync word and roughly a dozen frames.

The problem

Raw captures arrive faster than analysts can read them.

Terrestrial HF, VHF and UHF recordings come from different sensors and places. The parameters that matter are rarely written down.

01

Manual analysis

Sampling rate, modulation, error correction and interleaving are worked out by hand, one signal at a time.

02

Missing parameters

A raw IQ file has no header, and different sensors record different parameters.

03

Mixed formats

IQ and WAV store the same waveform differently and need separate processing paths.

04

No confidence score

Hand-tuned results are hard to reproduce, and nothing says how sure the answer is.

How it works

One upload, five stages, each one inspectable.

Nothing is assumed about the signal. Every stage reports what it measured, what it tried, and how confident it is, and any estimate can be overridden by hand.

1. Ingest

WAV (mono or I/Q) and raw IQ in four sample formats become one complex-sample stream.

live

2. Identify

Centre frequency, bandwidth, SNR, symbol rate and modulation, from a power spectrum and a feature-based classifier, cross-checked by a CNN trained on public data.

live

3. Demodulate

Timing and carrier recovery, then constellation, eye diagram and the raw bitstream.

live

4. De-interleave and decode

Resolves bit mapping and phase ambiguity, de-interleaves, and decodes convolutional, LDPC and Reed-Solomon codes.

live

5. Correlate and report

Finds frame length and sync word, separates header from payload, recovers the message and writes the PDF report.

live

Limits

What it cannot do yet.

Stated up front, because an operator should know where to stop trusting the output.

  • Not yet validated on live capturesDevelopment and testing so far use generated signals and a public simulated dataset.
  • LDPC needs a known parity-check matrixBuilt-in codes are found automatically; other codes work once you upload their matrix. Recovering an unknown matrix from noisy bits is an open research problem.
  • Interleaver type and size are supplied by the operatorThe start offset is found automatically, the type and size are not.
  • Needs a repeating sync wordFraming and Reed-Solomon alignment depend on it, with roughly a dozen frames for long frames.
  • Convolutional codes up to constraint length 9Rate 1/2 and 1/3, no puncturing, hard-decision decoding.
  • One signal per fileOverlapping carriers, frequency hopping and OFDM are not handled.
